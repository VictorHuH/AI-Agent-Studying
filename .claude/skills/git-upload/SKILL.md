# 自动上传学习内容

## 何时用
用户要求把学习仓库的当前改动上传/提交/推送。典型触发语：
- "将本次学习内容上传"
- "上传一下学习内容"
- "提交推送到 GitHub"
- "同步到远程仓库"

本 skill 只作用于学习仓库（`c:\Users\Administrator\Desktop\AI\Studying`）。用户已明确授权自动执行完整流程（add → commit → push），不要逐步征求确认。

## 流程
1. **查改动**：`git status --short`。若没有任何改动，告知用户"工作区干净，没有可提交的内容"并结束，不要制造空提交。
2. **定主题**：commit message = 本次学习主题（纯主题风格，如「11-工程化」「多Agent与SubAgent」，不带前缀）。推断依据按优先级：
   1. 本次会话刚学/刚写的内容（对话上下文最准）
   2. 改动的文件名（如新增 `11-工程化.md` → 主题「11-工程化」）
   若两处都推断不出或多个主题混杂，用一句话向用户确认后再提交。
3. **提交**：
   ```bash
   git add -A
   git commit -m "主题"
   ```
4. **推送**：`git push`。若被拒绝（远程有新提交），`git pull --rebase` 后再 push 一次；仍失败则把报错原样展示给用户处理，不要自行 force push。
5. **汇报**：一句话说清结果——commit hash、提交文件数、推送是否成功。

## 注意
- 主题以对话为准：用户刚学完的东西比文件名更能代表"本次主题"
- chroma_db、__pycache__ 等生成物也在 `add -A` 范围内——这是用户明确选择的策略，不要替用户"优化"
- 绝不 force push，绝不改写历史
