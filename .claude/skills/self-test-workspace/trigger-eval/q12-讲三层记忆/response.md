## 先一句话版本

把 Agent 想成一个人在干活：

- **短期记忆**：这次对话里"对方刚说了什么"——只要这场对话没结束就记得。
- **工作记忆**：做一道多步题时草稿纸上的中间结果——"上海32了、北京30了，还差广州"。
- **长期记忆**：日记本。今晚关机睡觉，明天翻开还在。

## 最容易混的点：短期和工作的"物理载体"是同一个

看代码你会发现，短期记忆和工作记忆都存在同一个 `messages` 列表里，没有两个数据结构。区别在**内容和边界**：

- 短期记忆 = messages 里"对话轮次"那部分：用户说一句、Assistant 答一句，就是 `chat_multi_turn` 那套。
- 工作记忆 = messages 里"任务内部推理轨迹"那部分：一个任务里的 Thought → Action → Observation 序列。

为什么笔记说 ReAct 的工作记忆是"免费的"？因为 ReAct 循环本来就必须把 Thought/Action 追加进 messages，模型下一轮才能接着推理（就是 `run_agent` 里那两行 `messages.append`）。循环要跑，scratchpad 就自动有了——一行额外代码不用写。纯 FC 没有这个中间过程，所以只有短期层、没有工作层。

生命周期排序：**工作（单次任务）< 短期（整个会话）< 长期（跨会话/永久）**。会话一结束，messages 整个列表被丢弃，短期和工作一起消失；只有沉淀进 Chroma 的活下来。

## 长期记忆为什么长这样（Chroma + 检索）

直觉方案是"把事实写进个文件，每次全塞进 prompt"。问题是记忆会越攒越多，总有一天塞不进窗口。所以笔记的方案是**检索式记忆**：存的时候 embedding 进 Chroma，用的时候只取跟当前问题最相似的 Top-K 条塞进 system prompt。这就是为什么它能直接复用 RAG 那套——机制一模一样，只是数据源从"简历 PDF 块"换成"对话事实"。

## 拿笔记里那个上海旅游演示对号入座

- 第2轮问"我刚才说要去哪旅游来着"→ 模型翻 messages（**短期**）看到上海 → 短期生效
- ReAct 第4步 Thought"广州35最热、北京30最冷"→ **工作**记忆，任务内中间结果
- 程序重跑一遍，第1轮就召回"用户打算去上海旅游"→ **长期**，只有这层跨会话不丢

顺带一个笔记里埋了但容易漏的坑：**短期记忆有天花板**（上下文窗口）。ReAct 的 messages 每轮还追加 Thought/Action/Observation，膨胀得比普通聊天快得多；长期记忆就是突破天花板的手段——把重要事实从 messages 沉淀出去，窗口满了也不丢。
